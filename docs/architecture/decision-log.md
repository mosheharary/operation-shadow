# Decision log

Short records of implementation decisions made after the plan was approved. The approved plan itself is
`implementation-plan.md`.

## M1 — Foundation (2026-10-15)

| # | Decision | Why |
|---|---|---|
| D1 | Pin package versions published at least 7 days ago, enforced by pnpm `minimumReleaseAge: 10080`. For example: Next 16.4.0 rather than 16.4.1, React 19.3.0, Better Auth 1.7.7, R3F 9.8.1, Playwright 1.64.0 | Supply-chain hygiene. pnpm 12 auto-excluded the brand-new pins, and we chose to keep the safeguard instead |
| D2 | Dependency install scripts are deny-by-default: pnpm `allowBuilds` lists only esbuild, sharp and unrs-resolver | pnpm 11+ replaced `onlyBuiltDependencies` with `allowBuilds`. The listed packages only fetch or verify prebuilt binaries |
| D3 | ESLint 9.39.5, not 10 | `eslint-plugin-react`, `eslint-plugin-import` and `eslint-plugin-jsx-a11y`, all used by `eslint-config-next`, don't declare ESLint 10 support yet. Dev-only tool |
| D4 | TypeScript 6.0.3, not 7 | `typescript-eslint` 8.71 requires TypeScript below 6.1 |
| D5 | One hoisted `node_modules` in a Docker volume; source bind-mounted; the entrypoint re-installs when the lockfile hash changes | Works without host Node. Keeps Linux binaries out of the macOS tree. Dependencies stay in sync automatically |
| D6 | Better Auth schema generated by its own CLI (`auth@1.7.7 generate` with `apps/web/better-auth.cli.ts`) | The schema exactly matches what the installed version expects. Regenerate rather than hand-edit |
| D7 | Dev login = email/password enabled only when the guard allows it, with `disableSignUp: true`. Operators are created by the seed script through Better Auth's internal adapter (`method: 'admin'`) | No public sign-up endpoint exists even locally. In production the email/password routes are disabled entirely |
| D8 | The migration runner is a separate entry point (`@operation-shadow/db/migrate`), not exported from the package index | It depends on Node file paths (`import.meta.dirname`), which don't exist inside Turbopack's server bundle |
| D9 | Readiness compares the latest applied migration timestamp with the newest entry in the migration journal bundled into the build | Detects a deploy whose migrations haven't run yet |
| D10 | Browser tests run in the Playwright image with `network_mode: service:app` | The browser uses the same origin the app is configured with (`http://localhost:3000`). That satisfies auth origin checks and avoids Chromium's HTTPS upgrade of non-localhost hostnames, which broke the first run |
| D11 | Session-dependent pages declare `dynamic = 'force-dynamic'`, and `getSession()` reads request headers before touching auth | `next build` was otherwise trying to pre-render `/` and needed runtime secrets |
| D12 | The production-like container listens on 3001 both inside and outside | Its auth base URL (`http://localhost:3001`) must equal the origin the browser uses |

## M2 — Playable vertical slice (2026-10-15)

| # | Decision | Why |
|---|---|---|
| D13 | Characters are procedural low-poly mannequins (`render/figure.ts`) with per-role looks, not CC0 rigged models | One consistent "miniature diorama" style, no licence risk, no asset pipeline needed yet. Swappable for authored models in M5 |
| D14 | Boats and drivable vehicles are deferred. The Marine Operator swims and dives instead; rowboats are props. Watchtowers are guard posts operatives cannot climb | Keeps the slice focused on the core stealth loop. Both are listed in the M5 backlog |
| D15 | The game does its own pointer picking every frame: a ray march over terrain, pier decks and the water surface, plus a raycast against tagged hitboxes | R3F pointer events only fire when the mouse moves, so hover went stale while units or the camera moved, and clicks on water landed on the sea bed |
| D16 | The right-click context action never chooses a lethal ability; knife, rifle, pistol and harpoon are only used from the ability bar | "Non-lethal is equally viable" (Q6) and avoids accidental kills. Scoring never rewards kills |
| D17 | Controls follow plan §6: left-click selects (Shift adds, drag box), right-click gives the context order (double right-click runs, Shift queues). Ability slots use R G V B Y H N J U K. All keys come from one binding table | Keys stay clear of camera keys (WASD, Q/E) and stances (Z/C/X). The table makes the M5 remapping screen a UI task only |
| D18 | Sound effects and ambience are synthesised at runtime. Music uses the approved Lyria tracks with state crossfades. Voice lines are generated one per line by Gemini TTS at build time (`make voice-bank`), with a text-only fallback | No sample libraries to license. Per-line files let the dialogue director vary, cut and prioritise lines. 108 lines cost about $0.07 and take 1.8 MB |
| D19 | The opening camera looks from the insertion point toward the primary objective, snapped to the nearest isometric diagonal | The first default faced the map corner and showed mostly void |
| D20 | `react-hooks/immutability` is off for `game/render`, `game/input` and `game/camera` | R3F code creates three.js objects once and mutates them in `useFrame`, which is R3F's documented pattern. The React Compiler is not enabled |
| D21 | Game settings (quality, volumes, subtitles, edge scroll, reduced shake, noise rings, FPS readout) live in per-browser storage for now | Account-level sync through `user_preferences` belongs to M4 (persistence) |
| D22 | Added a transient `bell` game event | The audio needs to know when an alarm bell rings. Events are never saved, so saves and determinism are unaffected |
| D23 | Mission entries declare their squad rules (`squad.required/min/max`) statically; a test keeps them equal to the built mission | The briefing and play pages validate a squad without generating the level on the server |
| D24 | Browser tests read state through a read-only `window.__OS_GAME__` probe and drive the game with real mouse and keyboard input | Tests exercise the actual input path. The probe cannot issue orders, so it is not a cheat channel |

## Art pass toward the approved concept (2026-10-15, after M2)

The first M2 build rendered flat-coloured primitives; the user expected the look of the approved concept
`samples/images/env_coastal_night.jpg`. Comparison sheet: `docs/art/art-pass-2026-10-15.jpg`.

| # | Decision | Why |
|---|---|---|
| D25 | Turbopack's persistent dev cache is off (`experimental.turbopackFileSystemCacheForDev: false`) | On the Docker bind mount it goes stale on every dev-server restart and sends the browser into a reload loop ("HMR hash mismatch"). Costs a slower first compile |
| D26 | Surfaces use 14 CC0 texture sets from Poly Haven (512 px WebP, fetched and MD5-verified by `make textures`) through world-space triplanar materials | Q2 approved "procedural + CC0". World-space projection textures procedural geometry without UV work. Roofs alone use UV-mapped slabs so the tiles follow the slope |
| D27 | The terrain blends eight surface layers from two array textures, weighted per vertex from the level's surface map, with triplanar rock on steep ground, wet shorelines and render-only crag noise on cliffs (0.5 m render mesh) | Two samplers for eight materials keeps the shader cheap. Gameplay still uses the 1 m heightfield; the crags only displace impassable cliff faces |
| D28 | Post-processing on the High preset: N8AO ambient occlusion, bloom, a gentle tilt-shift, vignette and ACES tone mapping (`@react-three/postprocessing` 3.1.3, `postprocessing` 6.39.5). The Performance preset has none | This finish is most of the concept's "miniature diorama" look. 3.2.0 was too new for the 7-day release rule |
| D29 | Harbour details (stone quay walls with coping, plank piers on braced posts, ladders), faceted mossy rocks, detailed props, textured buildings, lamp halos and the water (wave normals, fresnel sheen, moon glints, shore foam, diorama cut edge) are all generated from level data at load | Every coastal layout gets them without hand-placed art |
| D30 | Coastal generator v2 adds solid barrels, crates and nets against building walls and along the quay, kept clear of doors, routes, posts and other props | The concept's clutter doubles as cover. Mission validation (stealth route, objective chain) still passes |
| D31 | Browser tests run on the Performance preset | SwiftShader renders post-processing at about 1 FPS, which would slow the simulation clock far below real time |

## Campaign and tutorial (2026-10-15, start of the "finish all milestones" goal)

| # | Decision | Why |
|---|---|---|
| D32 | Three more hand-built templates (alpine `alpine@1`, rail `rail@1`, training `training@1`) share a `LevelKit` of building, fence, lamp and clutter helpers. Every template exposes named slots (targets, items, prisoners, markers) | Missions, including the AI-generated ones in M3, choose objectives by slot instead of coordinates, so a spec can never place an objective inside a wall |
| D33 | Missions are described by a declarative `MissionSpec` (template, seed, environment, guard density, objectives on slots, squad rules, alarm limit, par time, timed events) compiled and validated by `compileMission`; `fallbackSpec` makes a valid spec offline | The same path serves the authored campaign, Gemini output (M3) and the no-AI fallback; validation (stealth route, objective chain) runs on all of them |
| D34 | The campaign is six missions: Boot Camp (tutorial), Silent Tide, White Silence, Iron Junction, Frozen Ledger, Last Light | "Multi-mission campaign" (Q11), covering coastal, alpine and rail settings, day, dusk, dawn and night, and all six specialists |
| D35 | The tutorial is a guided Boot Camp mission: one instruction at a time in a side panel, advancing when the player does it, with a pulsing ground marker; it can be hidden or skipped. Key names come from the live binding table | First-time players learn by doing in a safe map. A unit test plays the whole script with the real right-click logic and requires extraction with zero detections |
| D36 | An entity order may carry the clicked point (`target.at`). A fence is approached and cut at the cell nearest that point (or the operative), not at the fence's midpoint | Found by the tutorial test: cutting a long fence sent the Engineer to its middle, past the gate sentry |
| D37 | Approach orders no longer re-plan in the middle of a climb or ladder link | The re-plan restarted the climb forever; regression test in `scenarios.test.ts` |
