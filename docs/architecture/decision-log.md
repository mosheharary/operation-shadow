# Decision log

Short records of implementation decisions made after the plan was approved. The approved plan itself is
`implementation-plan.md`.

## M1 — Foundation (2026-10-15)

| # | Decision | Why |
|---|---|---|
| D1 | Pin package versions published at least 7 days ago, enforced by pnpm `minimumReleaseAge: 10080`. For example: Next 16.4.0 rather than 16.4.1, React 19.3.0, Better Auth 1.7.7, R3F 9.8.1, Playwright 1.64.0 | Supply-chain hygiene. pnpm 12 auto-excluded the brand-new pins, and we chose to keep the safeguard instead |
| D2 | Dependency install scripts are deny-by-default: pnpm `allowBuilds` lists only esbuild, sharp and unrs-resolver | pnpm 11+ replaced `onlyBuiltDependencies` with `allowBuilds`. The listed packages only fetch or verify prebuilt binaries |
| D3 | ESLint 9.39.5, not 10 | `eslint-plugin-react`, `eslint-plugin-import` and `eslint-plugin-jsx-a11y`, all used by `eslint-config-next`, don't declare ESLint 10 support yet. Dev-only tool |
| D4 | TypeScript 6.0.3, not 7 | `typescript-eslint` 8.71 requires TypeScript below 6.1 |
| D5 | One hoisted `node_modules` in a Docker volume; source bind-mounted; the entrypoint re-installs when the lockfile hash changes | Works without host Node. Keeps Linux binaries out of the macOS tree. Dependencies stay in sync automatically |
| D6 | Better Auth schema generated by its own CLI (`auth@1.7.7 generate` with `apps/web/better-auth.cli.ts`) | The schema exactly matches what the installed version expects. Regenerate rather than hand-edit |
| D7 | Dev login = email/password enabled only when the guard allows it, with `disableSignUp: true`. Operators are created by the seed script through Better Auth's internal adapter (`method: 'admin'`) | No public sign-up endpoint exists even locally. In production the email/password routes are disabled entirely |
| D8 | The migration runner is a separate entry point (`@operation-shadow/db/migrate`), not exported from the package index | It depends on Node file paths (`import.meta.dirname`), which don't exist inside Turbopack's server bundle |
| D9 | Readiness compares the latest applied migration timestamp with the newest entry in the migration journal bundled into the build | Detects a deploy whose migrations haven't run yet |
| D10 | Browser tests run in the Playwright image with `network_mode: service:app` | The browser uses the same origin the app is configured with (`http://localhost:3000`). That satisfies auth origin checks and avoids Chromium's HTTPS upgrade of non-localhost hostnames, which broke the first run |
| D11 | Session-dependent pages declare `dynamic = 'force-dynamic'`, and `getSession()` reads request headers before touching auth | `next build` was otherwise trying to pre-render `/` and needed runtime secrets |
| D12 | The production-like container listens on 3001 both inside and outside | Its auth base URL (`http://localhost:3001`) must equal the origin the browser uses |
